# PostgreSQL Support Test Guide

DiagramFlow의 PostgreSQL 지원 기능을 테스트하기 위한 가이드입니다.

## 개요

DiagramFlow는 PostgreSQL을 다음 방식으로 지원합니다:

1. **DDL Import**: PostgreSQL DDL을 파싱하여 다이어그램 생성
2. **DDL Export**: 다이어그램에서 PostgreSQL DDL 생성
3. **Reverse Engineering**: 기존 PostgreSQL 데이터베이스에서 스키마 추출
4. **타입 매핑**: PostgreSQL 특화 데이터 타입 지원

## 테스트 환경

- 서버: http://localhost:5000
- 브라우저: Chrome, Firefox, Safari 등
- PostgreSQL: 12+ (선택사항, Reverse Engineering 테스트 시 필요)

## 1. PostgreSQL DDL Import 테스트

### 테스트 시나리오 1: 기본 타입

PostgreSQL의 기본 데이터 타입이 제대로 import되는지 확인합니다.

```sql
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE
);

COMMENT ON TABLE users IS '사용자 정보';
COMMENT ON COLUMN users.id IS '사용자 ID';
COMMENT ON COLUMN users.username IS '사용자명';
COMMENT ON COLUMN users.email IS '이메일';
COMMENT ON COLUMN users.is_active IS '활성 상태';
COMMENT ON COLUMN users.created_at IS '생성일시';
COMMENT ON COLUMN users.updated_at IS '수정일시';
```

**예상 결과:**
- ✅ `users` 테이블 생성됨
- ✅ `id` 컬럼이 `integer` 타입이고 `auto_increment=true`
- ✅ `username`이 `string(50)` 타입이고 `NOT NULL`
- ✅ `email`이 `UNIQUE` 제약조건 가짐
- ✅ `is_active`가 `boolean` 타입이고 `DEFAULT TRUE`
- ✅ `created_at`의 DEFAULT가 `CURRENT_TIMESTAMP`
- ✅ 모든 COMMENT가 logical_name으로 설정됨

### 테스트 시나리오 2: PostgreSQL 특화 타입

PostgreSQL 전용 데이터 타입이 제대로 지원되는지 확인합니다.

```sql
CREATE TABLE products (
    id UUID PRIMARY KEY,
    name VARCHAR(200) NOT NULL,
    metadata JSONB,
    price NUMERIC(10,2),
    tags TEXT[],
    image BYTEA,
    created_at TIMESTAMP DEFAULT NOW()
);

COMMENT ON TABLE products IS '제품 정보';
COMMENT ON COLUMN products.id IS '제품 UUID';
COMMENT ON COLUMN products.name IS '제품명';
COMMENT ON COLUMN products.metadata IS '메타데이터 (JSON)';
COMMENT ON COLUMN products.price IS '가격';
COMMENT ON COLUMN products.image IS '이미지 데이터';
```

**예상 결과:**
- ✅ `id`가 `string(36)` 타입 (UUID)
- ✅ `metadata`가 `json` 타입 (JSONB)
- ✅ `price`가 `integer` 타입 (NUMERIC)
- ✅ `image`가 `text` 타입 (BYTEA)
- ✅ `created_at`의 DEFAULT가 `CURRENT_TIMESTAMP`

### 테스트 시나리오 3: SERIAL/BIGSERIAL

PostgreSQL의 auto-increment 타입인 SERIAL과 BIGSERIAL이 제대로 처리되는지 확인합니다.

```sql
CREATE TABLE logs (
    id BIGSERIAL PRIMARY KEY,
    user_id INTEGER,
    action VARCHAR(100),
    log_data TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

COMMENT ON TABLE logs IS '로그 정보';
COMMENT ON COLUMN logs.id IS '로그 ID';
COMMENT ON COLUMN logs.user_id IS '사용자 ID';
COMMENT ON COLUMN logs.action IS '액션';
COMMENT ON COLUMN logs.log_data IS '로그 데이터';
```

**예상 결과:**
- ✅ `id`가 `bigint` 타입이고 `auto_increment=true`
- ✅ PRIMARY KEY 제약조건 설정됨
- ✅ 모든 컬럼이 올바르게 파싱됨

### 테스트 시나리오 4: 복잡한 제약조건

```sql
CREATE TABLE orders (
    id SERIAL PRIMARY KEY,
    order_number VARCHAR(50) UNIQUE NOT NULL,
    user_id INTEGER NOT NULL,
    total_amount DECIMAL(15,2) DEFAULT 0.00,
    status VARCHAR(20) DEFAULT 'pending',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE order_items (
    id SERIAL PRIMARY KEY,
    order_id INTEGER NOT NULL,
    product_id UUID NOT NULL,
    quantity INTEGER DEFAULT 1,
    unit_price DECIMAL(10,2) NOT NULL,
    FOREIGN KEY (order_id) REFERENCES orders(id) ON DELETE CASCADE
);

COMMENT ON TABLE orders IS '주문 정보';
COMMENT ON TABLE order_items IS '주문 항목';
```

**예상 결과:**
- ✅ 두 테이블 모두 생성됨
- ✅ FOREIGN KEY 제약조건 인식 (현재는 스킵)
- ✅ DEFAULT 값들이 올바르게 설정됨

## 2. PostgreSQL DDL Export 테스트

### 테스트 절차

1. 브라우저에서 DiagramFlow 접속
2. 새 다이어그램 생성
3. Database Type을 **PostgreSQL**로 선택
4. 테이블 추가:
   - 이름: `users`
   - 컬럼:
     - `id` (integer, PK, auto_increment)
     - `username` (string(50), NOT NULL)
     - `email` (string(100), UNIQUE)
     - `is_active` (boolean, DEFAULT true)
     - `created_at` (datetime, DEFAULT CURRENT_TIMESTAMP)

5. DDL 생성 버튼 클릭 (Database Type: PostgreSQL)

**예상 DDL 결과:**

```sql
-- ================================================
-- PostgreSQL DDL Generated by Python ERD Tool
-- Diagram: My Diagram
-- ================================================

DROP TABLE IF EXISTS users CASCADE;

CREATE TABLE users (
  id SERIAL NOT NULL,
  username VARCHAR(50) NOT NULL,
  email VARCHAR(100),
  is_active BOOLEAN DEFAULT TRUE,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (id),
  UNIQUE (email)
);
```

**검증 사항:**
- ✅ `SERIAL` 타입이 사용됨 (INTEGER가 아닌)
- ✅ `DROP TABLE IF EXISTS ... CASCADE` 문 포함
- ✅ `DEFAULT CURRENT_TIMESTAMP` (따옴표 없음)
- ✅ `DEFAULT TRUE` (따옴표 없음)
- ✅ PRIMARY KEY와 UNIQUE 제약조건 포함

## 3. PostgreSQL Reverse Engineering 테스트

**사전 요구사항**: PostgreSQL 서버 실행 중이어야 함

### 테스트 절차

1. PostgreSQL에 테스트 데이터베이스 생성:

```sql
CREATE DATABASE testdb;
\c testdb

CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) UNIQUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE posts (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(200) NOT NULL,
    content TEXT,
    published BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

COMMENT ON TABLE users IS '사용자';
COMMENT ON TABLE posts IS '게시글';
COMMENT ON COLUMN users.username IS '사용자명';
COMMENT ON COLUMN posts.title IS '제목';
```

2. DiagramFlow에서 Reverse Engineering:

```bash
curl -X POST http://localhost:5000/api/import/database \
  -H "Content-Type: application/json" \
  -d '{
    "db_type": "postgresql",
    "connection": {
      "host": "localhost",
      "port": 5432,
      "user": "postgres",
      "password": "password",
      "database": "testdb"
    },
    "schema": "public"
  }'
```

**예상 결과:**
- ✅ `users`와 `posts` 테이블 모두 import됨
- ✅ 모든 컬럼이 올바른 타입으로 매핑됨
- ✅ SERIAL 컬럼이 auto_increment로 인식됨
- ✅ FOREIGN KEY 관계가 Relationship으로 생성됨
- ✅ COMMENT가 comment 필드로 저장됨

## 5. 통합 테스트

### 시나리오: PostgreSQL → DiagramFlow → PostgreSQL

1. PostgreSQL DDL을 import
2. 다이어그램 편집 (테이블 추가, 컬럼 수정 등)
3. PostgreSQL DDL로 export
4. Export된 DDL을 새 PostgreSQL 데이터베이스에 실행
5. 새 데이터베이스에서 다시 Reverse Engineering
6. 원본과 비교

**예상 결과:**
- ✅ 데이터 손실 없음
- ✅ 타입 변환 정확
- ✅ 제약조건 유지
- ✅ COMMENT 보존

## 알려진 제한사항

1. **배열 타입**: TEXT[], INTEGER[] 등의 배열 타입은 현재 TEXT로 매핑됨
2. **ENUM 타입**: PostgreSQL ENUM은 현재 VARCHAR로 매핑됨
3. **복합 타입**: 사용자 정의 복합 타입은 지원되지 않음
4. **상속**: PostgreSQL 테이블 상속은 지원되지 않음
5. **파티셔닝**: 파티션 테이블은 일반 테이블로 처리됨

### E-commerce 스키마

```sql
-- Users
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(100) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Products
CREATE TABLE products (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(200) NOT NULL,
    description TEXT,
    price NUMERIC(10,2) NOT NULL,
    stock_quantity INTEGER DEFAULT 0,
    metadata JSONB,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Orders
CREATE TABLE orders (
    id BIGSERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id) ON DELETE SET NULL,

    total_amount NUMERIC(15,2) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Order Items
CREATE TABLE order_items (
    id BIGSERIAL PRIMARY KEY,
    order_id BIGINT REFERENCES orders(id) ON DELETE CASCADE,
    product_id UUID REFERENCES products(id),
    quantity INTEGER NOT NULL,
    unit_price NUMERIC(10,2) NOT NULL,
    subtotal NUMERIC(15,2) NOT NULL
);

-- Comments
COMMENT ON TABLE users IS '사용자 정보';
COMMENT ON TABLE products IS '제품 정보';
COMMENT ON TABLE orders IS '주문 정보';
COMMENT ON TABLE order_items IS '주문 항목';
```
